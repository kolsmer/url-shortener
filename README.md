# URL Shortener - Сервис сокращения ссылок

Простой и быстрый сервис для создания коротких ссылок. Вместо длинного URL вроде `https://www.example.com/very/long/path` вы получаете короткую ссылку `http://localhost:8080/baaaap`.

## Как это работает

### Создание короткой ссылки

Отправляете длинный URL:
```bash
curl -X POST http://localhost:8080/api/v1/shorten \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.google.com"}'
```

Получаете ответ с коротким кодом:
```json
{"code":"baaaao","url":"http://localhost:8080/baaaao"}
```

### Переход по короткой ссылке

Открываете `http://localhost:8080/baaaao` в браузере → вас автоматически редиректит на оригинальный длинный URL.

## Что внутри

**Язык:** Go (Golang) — быстрый язык программирования

**Компоненты:**
- **HTTP сервер** — принимает запросы на сокращение и редирект
- **PostgreSQL** — база данных, хранит оригинальные URL и коды
- **Redis** — кэш в оперативной памяти для быстрого доступа
- **Prometheus** — сбор метрик для мониторинга

**Логика кодирования:**
- ID из БД кодируется в base36 (буквы a-z и цифры 0-9)
- Минимальная длина кода — 6 символов
- Один и тот же URL всегда дает один и тот же код (нет дублей)

## Запуск

**Требует:**
- Docker и Docker Compose
- Go 1.25+
- k6 (для нагрузочного тестирования)

**Старт базы данных:**
```bash
docker-compose up -d
```

**Запуск сервера:**
```bash
go run cmd/server/main.go
```

Сервер слушает на `http://localhost:8080`

## API

### Создание короткой ссылки
```
POST /api/v1/shorten
Content-Type: application/json

{"url": "https://example.com/long/path"}
```

**Ответ (201):**
```json
{
  "code": "baaaap",
  "url": "http://localhost:8080/baaaap"
}
```

### Переход по ссылке
```
GET /{code}
```

**Ответ:** 307 редирект на оригинальный URL

### Просмотр метрик
```
GET /metrics
```

Prometheus формат для мониторинга

## Результаты нагрузочного тестирования (k6)

Тест моделировал реальную нагрузку: от 200 до 400 одновременных пользователей, каждый создает короткую ссылку и переходит по ней.

### Основные показатели

 **Все тесты пройдены успешно**

| Метрика | Результат |
|---------|-----------|
| Общее количество запросов | 849,990 |
| Успешные запросы | 97.09% (2.91% ошибок) |
| Среднее время ответа | 31.5 мс |
| 95-й перцентиль (p95) | 114.98 мс |
| 99-й перцентиль (p99) | 187.3 мс |
| Макс время ответа | 564.69 мс |
| Пропускная способность | 3,146 RPS |
| Итераций | 426,255 |

### Что это значит

- **Производительность:** ~3.1k RPS при 400 одновременных пользователях
- **Стабильность:** 97% успешных запросов, ошибки в основном из-за перегрузки DB
- **Быстрота:** Большинство ответов за 30-100 мс
- **Масштабируемость:** Система выдерживает высокую нагрузку, но для 5k+ RPS нужна инфраструктура 

### Нагрузочный сценарий

```
0-30с:    Нарастание до 200 пользователей
30-90с:   Стабильно 200 пользователей
90-120с:  Нарастание до 400 пользователей
120-180с: Стабильно 400 пользователей
180-210с: Плавное снижение до 0
```

Каждый пользователь в итерации:
1. Создает новую короткую ссылку (POST)
2. Ждет 0.05 сек
3. Переходит по ссылке (GET редирект)
4. Ждет 0.05 сек до следующей итерации

## Структура проекта

```
cmd/server/           - Точка входа приложения
internal/
  handler/            - HTTP обработчики
  service/            - Бизнес-логика (кодирование, валидация)
  storage/            - Работа с базой данных и кэшем
  metrics/            - Сбор метрик
  models/             - Структуры данных
configs/              - Конфигурация
migrations/           - Миграции БД
load-test.js          - K6 нагрузочный тест
docker-compose.yml    - PostgreSQL + Redis
```

## Кэширование

Redis кэширует:
- Оригинальные URL по коду (TTL 5 минут)
- Отрицательные результаты (TTL 1 минута)

Это снижает нагрузку на PostgreSQL при повторных запросах одного и того же кода.

## Запуск нагрузочного теста

```bash
k6 run load-test.js
```

Можно менять параметры в `load-test.js`:
- `target` — количество одновременных пользователей
- `duration` — длительность каждого этапа
- `thresholds` — допустимые пороги (время ответа, ошибки)
